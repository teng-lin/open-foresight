# Live note enhancement scheduling

The original `_onShorthandChanged` at `0x100aa6d00` first ignores identical text, then synchronizes bullets and stale mappings only while no enhancement is active. It records the manual edit and schedules the ordinary note save independently of enhancement scheduling.

With automatic enhancement enabled for the meeting, adding raw LF-delimited lines enters the immediate-target branch when `NotesEnhancer.hasEnhanceableScribbles` accepts the text. Growth counts all raw lines, including blanks; target indices count trimmed meaningful lines. A position is selected when it is new relative to the last successful shorthand list, differs exactly from that list, or is in the stale set. An empty selected set returns without installing or cancelling a debounce timer. A nonempty set cancels the debounce timer and either runs immediately or replaces the queued target set while generation is active. Requests replace the pending set; they do not union it.

Ordinary edits install the original 30-second debounce. Both the raw-edit timer closure and the live completion timer resolve to `0x100a4ce8c`; the closure checks mounted state and inactive enhancement before calling `_runLiveEnhancement`. The public pool object PP12749 is a `dart:core Duration`; its Smi microsecond field is 30000000. This corrects the previous port's two-second timer.

`hasEnhanceableScribbles` at `0x100a4cca0` splits by LF, trims through PP34639, filters nonempty meaningful content through PP34640, and returns true if any retained line is not already enhanced. Those callback code offsets are `0x655884` and `0x6ea5c0`, matching the already traced shorthand trim/filter callbacks. The helper is used for automatic/live admission; manual enhancement may update an already formatted enhanced line.

Live completion at `0x100a4c7d4–0x100a4c944` consumes a queued set immediately when automatic enhancement and meeting eligibility remain true. Otherwise changed raw text relative to the generation-start text schedules the same debounce. The queued flag and set are cleared before the next live invocation. The port forwards the targets to the recovered producer; a target does not itself force regeneration of an already accepted value, matching the recovered input planner. Automatic requests use the original live producer mode, which suppresses missed-topic generation independently of whether audio is being captured.

Application now connects these branches to note saves and live completion. Workspace clearing also clears pending targets; obsolete work cannot schedule requests into a new mapping owner. Waiting for unrelated native generation uses the port's existing retry timer, preserving target indices and live mode across that retry. The note readiness/reset boundary and macOS text-only startup cache retry are now connected; see [service recovery](reference-note-service-recovery.md). Vision/model-refresh behavior and broader exceptional outer lifecycle remain open. Later [production runtime acceptance](../validation/reference-production-runtime-acceptance.md) validates the Linux x86-64 CPU runtime subset on Ubuntu 24.04; full installers and Linux GPU acceptance remain separate.
