# Meeting Summary

`meetings.generate` with `kind: summary` runs the dedicated local Summary pipeline. The desktop Summary panel shows streamed previews, phase progress, cancellation, accepted versions, and the existing stale-transcript indicator. Other meeting artifacts keep their existing generation paths.

`summary_prompt.dart` preserves Foresight 1.0.0.28's exact full, incremental, MAP, and REDUCE prompt literals. Frozen fixture bytes and hashes are independent of the installed original and Git history. The expected brief has `# Overview` and `# Details`; Action Items is a separate feature. The frozen [prompt fixture](../../packages/foresight_core/test/fixtures/summary_prompts.json) and [workflow fixture](../../packages/foresight_core/test/fixtures/meeting_ai_reference.json) preserve the reference expectations.

`summary_generator.dart` cleans final transcript text and selects full generation at or below half the configured context in words, when the complete request fits its budget. Longer or over-budget input uses overlapping windows, sequential MAP requests, and a final REDUCE. The recovered defaults are `max(1500, floor(.375 * context))` words per window and `max(1200, floor(.8 * window))` words of advancement. Admission can shorten a window; advancement adjusts to retained words, so it never skips truncated-away evidence. Even a single MAP result receives a final REDUCE to apply the Overview/Details template. Multiple results use the recovered character-capped join, with Unicode-safe clipping and every topic retained.

An appended transcript can use incremental generation when its previous prefix fingerprint, model/tokenizer identity, context, prompt, and policy still match. A user-edited latest summary invalidates the checkpoint. Explicit generation refreshes unchanged input; the core's non-refresh path can reuse an identical checkpoint and otherwise requires 100 words. There is no new automatic-summary timer or preference.

Every request reserves output space and framing in addition to budgeting the complete system/user input. The helper's Encode RPC uses the embedding tokenizer, which is not proven compatible with the generation model. Summary therefore uses a conservative UTF-8 byte budget regardless of helper readiness. A future generation-bound tokenizer can improve context utilization; embedding token counts must not be presented as actual generation token counts. Output is capped at one quarter of context, between 128 and 1024 tokens. Each native child has a 120-second timeout.

After the recovered character-capped join, Open Foresight can further shorten MAP-result prefixes to fit the complete reduction request. This additional admission step is a deliberate port safeguard, not recovered original behavior. Clipping is recorded in the manifest and disclosed in the Summary panel. If prefixes for all topics cannot fit together, sequential balanced reduction subtrees combine them before the final REDUCE. Reduction framing is checked before map work; it does not impose a fixed minimum length on valid partials. Impossible framing or an unfit single transcript word fails with an actionable context error and preserves the accepted brief.

Open Foresight adds a separately versioned untrusted-source policy. LiteRT receives distinct system/user messages through the existing conversation protocol, with an empty tool list. Legacy text backends retain existing framing. Source instructions cannot enable tools or network access. The recovered ordered attribution rewrites run on preview/final output; a separate case-sensitive product guard removes residual capitalized channel attribution before selected attribution verbs after a Markdown bullet heading. Ordinary descriptions such as “Remote engineers” remain intact. These guards do not establish factual accuracy or enforce the model's entire formatting contract.

`SummaryCoordinator` (`application_services/summary_coordinator.dart`) owns each run under its public request ID and creates distinct native child IDs. Model operations, other summary runs, note enhancement, and foreground chat respect this owner between MAP calls. A liveness monitor interrupts a stalled child after cancellation, disconnect, workspace reset, or transcript/model replacement. The final synchronous snapshot check and database commit have no intervening await. Failed or canceled previews never become artifacts.

Schema 14 adds nullable `artifacts.manifest` and `meeting_summary_checkpoints`. Old summaries and edits survive migration without invented checkpoints. A SAVEPOINT commits the accepted artifact, its checkpoint, and a stable `meeting-summary-{id}` derived source together. The manifest records input revision/digest, generation identity, prompt/policy versions, effective model settings, tokenizer choice, output limit, generation mode, chunk count, and reduction clipping. Asynchronous embedding resumes through the existing pending-source mechanism. Generated summaries never feed this pipeline as transcript evidence.

The existing service/MCP generation operation returns after acceptance; service status carries `capture.meeting_summaries`. The desktop cancels with workspace-scoped `meetings.cancel_summary`. Transport disconnect cancellation maps the public lease to its active child. Progress is transient; accepted history and compatible checkpoints survive reopening.

Deterministic tests cover prompt bytes, dispatch boundaries, input coverage, token pressure, sanitation, Unicode clipping, cancellation, late transcript changes, atomic rollback, migrations, reopen/edit history, native conversation framing, compiled-service persistence, and desktop preview/cancel behavior. The source-export tests run without `.git`. See the [local validation record](../testing.md) for counts and limits. Real-model factual/format evaluation and the hosted isolated native desktop/service integration must pass before merge; widget and controlled-worker tests do not establish those results. Linux/Docker and macOS deployment-floor acceptance remain platform gates when unavailable on the development host.

Summary, question-generation and note inputs are built by `AttributedTranscript` (`attributed_transcript.dart`). A row whose persisted attribution is `attributed` leads its line with the participant's sanitized one-line name (`Name: text`). The name also has colons, colon look-alikes and braces neutralized in this form, so it cannot contain a forged statement or start a structured-transcript form; the stored rendered name and the search index keep the original. Once any row has a name, every other row reads `(unnamed speaker): text`, so a microphone row, or a row in an unknown, multiple, stale or unavailable state, never reads as the speaker before it; summary cleanup strips only `Microphone:` and `Remote:`, so this label survives. With no name anywhere, the input is the bare text it always was. The untrusted-name notice is added once by the prompt builder to every prompt that includes a name, and is never part of the transcript text: the system policy of each summary request (every map, reduce and incremental call), the question-generation instructions, and the note-enhancement prompt for live and final notes. It does not begin with a bracket, because saved-transcript extraction treats text starting with `[` as a structured transcript. Action extraction receives raw text only. A change to a rendered name bumps the meeting revision, so an in-flight summary is cancelled and regenerated from the current attribution, and accepted user edits of earlier artifacts are retained.
