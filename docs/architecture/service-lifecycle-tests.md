# Service lifecycle test coverage

This matrix records which tests cover each service boundary through each lifecycle transition. Rows are boundaries and columns are transitions. It was seeded from the 2026-10-19 lifecycle audit and updated through step 5 of the [service lifecycle fix plan](../plans/2026-10-19-service-lifecycle-fix-plan.md). Each later step updates the cells it closes, in the same change as its tests.

## Reading the matrix

- A cell lists tests as `FILE: test name`, where the name is the one given to `test`, without its group. A test declared in a loop is cited by the name of one instance. The file abbreviations are listed below.
- **fixture** marks coverage in which one side of the boundary is a fixture rather than production code. The fix plan requires at least one test with production code on both sides for each boundary.
- **GAP** means no test covers the transition. Where a planned test will close it, the cell names the fix-plan item, for example "PR 3 test 7".
- **n/a** means the transition does not exist at that boundary.

## Harness

Step 2 added the tools that later steps use to close these gaps deterministically:

- **`ServiceFaultProxy`** (`foresight_test_support/service_fault_proxy.dart`) relays a test isolate's connects to service endpoints and can hold, truncate, drop, inject and observe frames, and observe refused connects. It covers client-side boundaries.
- **Service gates** (`serviceGate` in `service.dart`) hold the real service at named points in `ApplicationService._close` (`close.begin`, `close.leases_terminated`, `close.helper_closed`, `close.listener_closed`, `close.before_frontend_release`, `close.before_record_delete`, `close.before_lock_release`), in the isolated frontend once its worker has exited (`frontend.draining`) and once its listener has closed but before it unlinks its public socket (`frontend.listener_closed`), before a starting owner tries its profile lock (`start.before_lock`), after a start that lost the lock and before it exits (`start.lock_contended`), after an owner takes its profile lock and claims its predecessor's endpoint record, before it decides about that record (`start.locked`), and after a request commits (`request.committed.<method>`). A `<point>.crash` file instead kills the isolate that reaches the point, standing in for a fatal worker fault. `FORESIGHT_SERVICE_GATES` is a test hook, kept only in builds compiled with `-DFORESIGHT_ENABLE_TEST_HOOKS=true`. PY: `test_release_service_ignores_lifecycle_gates` checks that the release binary ignores it.
- **`HookedServiceProcess`** (`foresight_test_support/hooked_service.dart`) runs `bin/service.dart` compiled with test hooks, so the ordinary `dart test` run exercises gates in a real child process.
- **`GatedHelper`** (`foresight_test_support/gated_helper.dart`) holds a closing service inside its helper shutdown. The built-service suite runs a byte-identical copy, `tests/service/gated_helper.py`.
