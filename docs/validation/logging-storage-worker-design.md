## Why the OS boundary remains necessary

Rejected logging aliases must not release application/SQLite POSIX locks. A metadata check followed by a regular-file open and mismatch close still races. [Linux close](https://github.com/torvalds/linux/blob/v6.12/fs/open.c) and [XNU vnode close](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_descrip.c) explain why same-process ordinary closes, including low-FD relocation, are unsafe. O_PATH on Linux does not provide a Darwin promotion strategy; O_EVTONLY is not claimed to avoid XNU POSIX unlocks.

One dedicated OS storage child alone opens **regular diagnostic data/lease/manifest files**. The writer isolate owns records, credits, rates, role/ownership ordering and bounded shared-memory IPC. The application coordinator owns an opaque native process context outside that isolate; a dedicated spawn isolate alone invokes blocking native spawn FFI. No application/coordinator isolate waits in spawn or file FFI. The child receives no Store/model/capture/application-native handles, opens no application database/ownership lock and creates no network endpoint or persistent logger. A3 backup/VFS semantics and frozen migrations stay unchanged. Foundation modules import Dart, the dedicated system-only diagnostic runtime, closed events and scoped storage; they do not import app bootstrap, RPC descriptors, Store or native runtime ownership.

Parent file-like opens are limited to DIRECTORY descriptors and internally created fresh kernel memfd/PSXSHM objects. Native lifecycle also creates birth pidfd and kqueue descriptors, atomic-CLOEXEC non-vnode kernel handles; these are not regular-file-open exceptions. O_DIRECTORY/no-follow rejects regular aliases before a descriptor exists; kernel allocation, rather than metadata prechecks, proves a fresh mailbox cannot alias an application inode. No parent command validator or IPC helper may data-open an ordinary regular-file candidate and then close it on rejection; the API accepts no caller-supplied bootstrap/data FD. Read-only metadata/path containment checks remain permitted. Direct DiagnosticStorage consumers are guarded to the worker and isolated filesystem fixtures; support/open-folder code cannot introduce an application-PID log-file open.

Child file operations retain no-follow/exclusive creation, effective UID, type, private-mode, link-count/size/identity/anchor validation, FD >=10, CLOEXEC and qualified actual directory/file mounts. Validate descriptors before **every** flock. Link/type/identity changes disable that sink and preserve prior bytes. Linux local filesystem support never proves APFS behavior. Darwin reverse aliases must also be tested: a child flock must not make the parent SQLite/application lock BUSY. Cover database, -shm, -wal, journal, application-lock, admission, lease, manifest and segment aliases, including actual name swaps and low-FD relocation.

## One fresh fixed-size kernel mailbox

Select ONE 16384-byte object per eligible session, conservatively charge BOTH process mappings as 32 KiB. No parent AF_UNIX socket, Unix channel path, stdio stream or kernel pipe is created for diagnostic traffic. A fixed private control page and its two cells are the entire channel, not a general shared-memory facility. memfd/shm FD creation is atomic-CLOEXEC even for unobserved fork/vfork/posix_spawn paths; all new directory/duplicate FDs use atomic O_CLOEXEC/F_DUPFD_CLOEXEC. Thus no entire-closed-OS spawn inventory is asserted and no transient socket residual is retained. Ordinary fork-before-exec memory exposure is not isolation against malicious same-process native code; all process memory was already visible under that trust boundary. No profile/database/log/lease FD rule is weakened.

Linux allocates internally with memfd_create(MFD_CLOEXEC|MFD_ALLOW_SEALING), mode 0600, length 16384; install F_SEAL_SHRINK|F_SEAL_GROW|F_SEAL_SEAL while preserving writes for IPC. Reject if creation/seals/type/UID/size/flags fail; no pathname or fallback regular file. Parent creation proves fresh kernel identity. Darwin internally uses O_CREAT|O_EXCL shm_open(mode 0600), verifies PSXSHM type/UID/size and atomic CLOEXEC, unlinks its known kernel name BEFORE spawn, ftruncates exactly once to 16384 and maps shared. Kernel PSXSHM cannot alias an application VNODE. It is mmap IPC, not read/write of an ordinary regular file; fstat mode lacks normal S_IFREG bits. Use actual public SDK/native C ABI for validation. A child with RW FD cannot resize after initialization: Linux seals forbid shrink/grow and XNU PSXSHM permits only one ftruncate per object lifetime. Actual zero/shrink/grow attempts in both processes are mandatory; a mere pre-stat does not prevent SIGBUS. Existing mappings do not grant a way to replace/truncate the object through a name. Other memory tampering remains untrusted protocol bytes, never pointers/length authority.

The page layout is native-ID/versioned and fixed, not supplied offsets: header 0..255, request cell at 256 (20-byte frame+8192 payload), reply cell at 8480 (20-byte frame+512 payload); remaining bytes are padding, never extra queued records. Header offsets:0 magic/version/header-size8 bytes;8 context-generation8; 16 applicationPID8;24 childPID atomic8; 32 nonce32;64 native-ID raw32;96 Dart-ID raw32;128 catalog-ID raw32; 160 parent-heartbeat8; 168 control-command8;176 control-ACK8;184 request-published8;192 request-consumed8;200 reply-published8;208 reply-consumed8;216 READY/state8;224 child-heartbeat8;232..255 reservedzero. Exact offsets/sizes/endianness are static assertions; native memory words little-endian on the supported x86-64/ARM64 targets, serialized OFDP header big-endian. Require 16384 divisible by page size<=16384 and lock-free atomic64 in both processes, otherwise storagePlatformUnsupported. No process-shared mutex or app wait is a fallback.

Each direction has one producer and one outstanding frame. Publisher writes only an empty cell and release-publishes a sequence; receiver acquire-loads it, snapshots bounded type/length, copies at most 4096 per C call into fixed local storage, rechecks sequence before parsing and acknowledges consumption. ### Mapping and context lifetime

A peer can corrupt its writable bytes but cannot change object size after initialization; process-local mappings/protection changes do not alter the other process's address space. Parent native context checks generation before every call. Never unmap/free/reuse a mapping while writer/spawn/watch/control FFI may reference it.
