## Context

The application service is shared by the Flutter desktop and the MCP adapter. Its lifetime is a side effect of desktop disconnect events, and that produces inconsistent behavior: an agent-only service never exits, while the same agent work is cut off one second after a desktop happens to close. The resource worth reclaiming is the models: the retrieval helper's embedding model, the generation runtime, the query-completion runtime, and the speech runtime while a recording exists. The embedding and generation models load during helper readiness; question detection and speech load on demand. With today's code the cheapest way to release them is to end the process, and the process is cheap to start again relative to the model loads.

### Current behavior, verified in code (`main` `ddab4116`)

Lifetime is driven entirely by `_desktopClients` and the `_desktopShutdown` timer in `ApplicationService._accept`:

- A connection joins `_desktopClients` only through `status` with `desktop: true` and the capability token, or through `security.attach_desktop`.
- When the **last** desktop connection closes and no approval host remains, a 1 s timer calls `close()`. Nothing else ever starts that timer.
- `close()` ends every lease: dispatched agent requests get `outcomeUnknown`, and requests still waiting for approval or helper readiness get a `closing` refusal ([ADR 0003](0003-structured-closing-refusals.md), landed in the lifecycle integration PR).
- MCP's `ServiceConnection` sends a plain `status`, so an MCP connection is never a desktop client and never starts the timer. `bin/mcp.dart` connects in `main` before any tool call and holds the socket until its host closes stdio; `ServiceConnection` reconnects on its next request after a lost connection.
- Host detach, by request or by EOF, stops recording at once ([ADR 0006](0006-stop-recording-on-host-disconnect.md)) and fails pending approvals (`AgentAccessGate.detach`). Approval-requiring calls with no host fail with `denied`, "Open the desktop app to review this operation"; pending approvals expire after two minutes.
- The helper is started once, at service startup (`ApplicationService._start` assigns `_ready = helper.start()`), and restarted from a bounded budget after an owned child exits. `_execute` awaits `_ready` for every operation whose `requiresHelper` is true, and `_results` awaits it separately for `answer.stream`. Each successful `_start` calls `onReady` once, after its first ping, and `onReady` runs `Domain.resume`, which applies the embedding model and **loads the generation runtime whenever one is registered or discoverable**. Only `Domain.noteEnhancementService` loads the generator lazily; the query-completion runtime loads on demand in `_detectQuestions`, and the speech runtime loads with a recording. `Helper.close` is terminal and runs the adopted-helper verification that `stop_if_idle` depends on; when that verification fails the helper is left running and the endpoint record is kept for the next launch to adopt.
- Model work runs with no request lease: automatic note enhancement from `_enhance` timers 30 s after a notes edit, proactive question detection and answers, `Domain.restoring`, pending-source draining and the serialized mutation tail, meeting indexing and Google maintenance; model configuration and dedicated query acquisition also remain guarded by their leases. Google maintenance, whose `refresh()` indexes and deletes through the helper. `Domain.index` waits for source work to be resumed before touching the helper, so a paused queue holds durable work without using a model.
- The only idle rule in the code base, the `inactivity` preference, stops a **recording** after 15 minutes without audio.
- `service.stop_if_idle` already has the installer's idleness predicate: no active or finishing recording and no in-flight lease other than `status`. It relies on no yield between its check and `close()`, and it checks `helper.shutdownVerified` only after `close()` has run.
- `Application.startBackground` runs `maintainGoogle` every minute for the life of the process: profile refresh, reminder notifications, and a Drive or Calendar refresh on its cadence. An agent-only service therefore syncs today; a desktop-only one stops syncing one second after the window closes. `preferences.set` and `google.refresh` are not MCP tools.
- The service holds the shared install lock for its lifetime. The Linux package hooks refuse a package change while it is held and never signal the owner; they run as root and see only a uid. `tools/install_macos.py` defers when a service is running unless given `--stop-services` and `--profile` for each, and defers while any desktop or MCP process from the bundle is alive. A desktop that meets a same-profile owner with a different `runtime_revision` fails inside `_connectCompatibleService`, which closes the client before the caller sees the reply, with "Stop the existing application service explicitly".
- The Linux runtime directory is per profile under `$XDG_RUNTIME_DIR` ([ADR 0005](0005-per-profile-linux-runtime.md)), with `$data/runtime/<id12>` as the fallback. logind removes `$XDG_RUNTIME_DIR` at the user's last logout unless lingering is enabled; a detached child stays in the login session's scope and survives logout unless `KillUserProcesses=yes`. The endpoint record holds only `data` and `runtime`.

| Situation | Today |
|---|---|
| Agent only, no desktop ever | The service and its models run until `--stop`. Leftover services with no clients are the observed symptom. |
| Desktop and agent connected, desktop closes | 1 s later the service exits, even mid-request. The agent's next call launches a replacement, so nothing is saved. |
| Desktop closes, agent calls later | A fresh service that now lives indefinitely, because no desktop ever attached to it. |
| Agent disconnects, desktop stays | No effect. Correct. |
| `--stop`, `--stop-if-idle`, SIGTERM | Everyone is closed. Correct. |

## Decision

**The desktop pins the process. Agents never pin it. With no desktop attached, the service exits once nothing is busy and the idle period has passed since the last agent work, or at once after the 1 s grace when the desktop leaves and no agent has worked within the period. Models go with the process.**

1. **No client disconnect interrupts agent work.** Desktop close stops recording and closes approvals at once (ADR 0006); agent requests in flight continue to their result. An executing serialized domain mutation (`domain.mutating > 0`, for example the indexing drain after a large import) holds both exit branches regardless of which client caused it, because `_serialize` carries no origin; desktop-only use keeps the one-second grace but waits for such a mutation to settle before the close begins. Other background model work holds only the idle branch and is cancelled on the desktop branch as today.
2. **Idle exit.** With no desktop connection and no approval host, nothing busy, and `now - lastAgentActivity >= serviceIdleMinutes` (default 30, a preference, fractional values allowed, 0 disables), the service calls `close()` as today's desktop timer does, with ADR 0003's closing protocol for any request that arrives meanwhile. `lastAgentActivity` is stamped when an agent request (fixed at lease creation from whether its connection is in `_desktopClients`) is dispatched (its work starts, after any approval or helper-readiness wait), excluding `status`, `security.*` and `service.*` (an installer's refused `--stop-if-idle` or a forged attach never counts as agent work), and again when its dispatched future and its stream cleanup have both settled (result, error or cancellation); it is unset until the first such request, and a never-attached service treats service start as its last activity, so a service launched by an agent host that only ever called `get_status` exits after one idle period. The default is unmeasured: the implementing PR records a cold start (process, helper, embedding and generation load) for a representative generator and reports those numbers here; the default stays 30 unless the repository owner changes it. It is a separate preference from `inactivity`, which is a microphone rule. An agent-only installation has no desktop and `preferences.set` is not an MCP tool, so it cannot tune the value; setting 0 from a desktop restores the agent-only leak by choice.
3. **No recent agent work keeps today's desktop-only exit.** When the last desktop connection leaves, no non-`status` agent request is waiting for helper readiness, dispatched or being cancelled, and `lastAgentActivity` is unset or older than the period, the service closes after the existing 1 s grace exactly as today, cancelling scheduled and executing background work; an agent dispatch during the grace cancels that close. The shortcut is decided only at departure: if it is not taken then, the idle rule governs until the next desktop attaches, and the timestamp ageing out later does not reactivate it. On the idle branch the busy list protects executing work. A desktop that opens and closes while an agent is mid-request or between recent calls therefore never ends the agent's service. Open agent connections do not pin: an agent whose service exited reconnects and relaunches on its next call, as it already does.
4. **Explicit stop is authoritative.** `--stop`, `--stop-if-idle` and SIGTERM close for everyone.
5. **Desktop-owned capabilities stop with the desktop.** Unchanged.
6. **Nothing else.** A same-profile owner of a different revision that implements this ADR exits by itself within one idle period once it is unpinned and not busy; an owner older than this ADR, with only the desktop-departure timer, may remain indefinitely and still needs the manual "stop the existing service" step. An automated idle stop from the desktop's startup path was drafted and dropped as not worth its text (see "Not in this change").

### Alternatives

- **(a) This decision** (revision 1 with corrections).
- **(b) Keep today's rule and fix only the agent-only leak.** Rejected: it keeps the desktop-close interruption of agent work.
- **(c) Resident with models kept loaded.** Rejected: an agent-only service holds gigabytes forever.
- **(d) Resident per login session with model unload** (revisions 2 and 3). Rejected after review: with background sync (Google and Granola maintenance with nobody attached) off by default, a resident process after the user quits does nothing but hold the profile and install locks, which required automated package-hook stops that a root hook cannot perform, a Quit-and-stop command, a socket watch as the session-end mechanism, and an invisible process in Activity Monitor after "Quit".
- **(e) Hybrid: desktop pins and keeps models warm; a working agent connection keeps an unloaded process; otherwise exit** (revision 4). Rejected after review: it needs a residency gate around every model consumer, a restartable `Helper.stop` that reaches into the adopted-helper verification and the restart budget, and a Google import-without-index path, and what it buys over (a) is one process start per idle gap for a connected host, on top of the model loads both pay. If `backgroundSync` (maintenance with nobody attached) is ever wanted it needs (f) or (d)'s residency as well as (e)'s unload; both build on this decision's busy predicate and `lastAgentActivity` stamp.
- **(f) Session-scoped daemon** (systemd user scope, macOS LaunchAgent). Not needed while nothing outlives its clients; revisit with (e).

## Consequences

- Agent work in flight is never interrupted by a desktop closing; the process stays until the agent has been idle for the period.
- Agent-only services stop leaking: they exit one idle period after the last agent request, and the models go with them.
- A desktop-only user keeps today's behavior exactly: warm models while the window is open, and the close begins one second after it closes, cancelling a model load or a scheduled enhancement in progress as today. As today, process exit, model reclamation and lock release follow cleanup, which includes finishing a recording's transcription and up to five seconds for an owned helper. A desktop user whose agent worked within the last `serviceIdleMinutes` sees the process linger for the remainder, visible in `status.lifetime.exit_after`.
- `--stop-if-idle` now also defers while background model work is executing; the installer reports it and the user retries.
- A long-lived MCP host whose service exited pays, on its next call, a process start plus the model loads it would pay under any unload scheme. That wait is inside the first tool call after the exit, so it is bounded by the host's tool timeout rather than by `ensureService`'s budget; the implementing PR's cold-start measurement records time to the first successful `search` after relaunch for the representative generator. Fix-plan 3.5 makes the relaunch transparent: the first request after an exit gets `notSent` or `closing` and is resent once; `outcomeUnknown` is never resent. A host that calls during the grace is dispatched and disarms the shortcut; a host that calls during the close itself is the case fix-plan test 7 covers.
- Starting an MCP host launches the service and loads the configured models even if no tool is ever called, because `bin/mcp.dart` connects in `main`; that service now exits after one idle period instead of living forever. Deferring the adapter's connect to its first tool call would remove that cost and is outside this change.
- Google and Granola maintenance runs while the process does, as today; with no desktop it ends at the idle exit instead of one second after the window closes. Reminder notifications and Drive or Calendar refresh that today keep running from a leaked agent-only service stop at its idle exit; delivering them with nobody attached is the background-sync want that alternative (e) records. `application-service.md`'s "independent of an open desktop window" becomes "while the service is running, which with no desktop attached is until the idle exit".
- Upgrade and uninstall are unchanged in the common case: nothing holds the install lock once clients are gone and the idle period has passed. The macOS installer defers while any desktop or MCP adapter process from the bundle is alive, as today; the Linux package hooks refuse while the service holds the install lock, whose close now begins at most one idle period after the last agent request.
- The process-boundary code stays exercised by every desktop-only close and idle exit; what changed is that no exit interrupts work or leaks.
- Idleness is wall-clock (`domain.clock`). A laptop that slept past the period exits on its first tick after wake.
- Residency does not change: same-user processes could already connect, approvals still need the attached desktop, and capability-token handling is unchanged: each replacement service generates a fresh token.
- An idle exit whose adopted helper cannot be verified behaves like today's desktop-close exit: the helper and its embedding model stay resident, the endpoint record is kept, and the next launch adopts it ([ADR 0002](0002-always-recover-after-unclean-shutdown.md)). Memory reclamation is guaranteed only for owned helpers.

## The rule

The service holds one timer, `_lifetime`, that reevaluates the exit predicate whenever a lease changes, a request completes, recording state changes, `_desktopClients` or the approval host changes, the helper reports a state change, an `application.changes` event fires, or a cancelled subscription settles, and at most every 30 s otherwise.

**Busy** (blocks the exit):

1. An in-flight lease other than `status`, as `_stopIfIdle` checks today (this covers a request still awaiting approval), or a non-`status` operation whose work has not settled: future operations are tracked by their `_execute` future, and stream operations (`answer.stream`, `google.sign_in`, `google.add_account`) by their subscription until it completes or `_cancelSubscription` settles. `_cancel` removes the lease and cancels delivery, but a cancelled `sources.search` can still be awaiting retrieval outside `_serialize`, so the operation stays busy, and stamps `lastAgentActivity`, only when its work and the stream cleanup settle. A cancelled operation must be able to settle: `Domain.waitForSourceWork` observes the request's cancellation, so a cancelled `sources.index` parked on a paused queue returns at once and leaves its committed source as durable pending work instead of holding the exit until someone resumes sources. Dispatch, for stamping, is the point where a lease leaves the waiting state (approval or helper readiness) and its work starts; a lease still waiting is refused with `closing` at shutdown and counts as busy but not as activity.
2. `application.recording != null`, exactly the active capture flag, including finishing and finalization.
3. Executing model work with no lease, read through `Application.backgroundBusy`: `_modelBusy` (a leased-operation guard), a `Domain` initialization or resume future still incomplete (not the `restoring` latch, which stays set when the helper never becomes ready), an active enhancement producer, including one whose entry was cleared, `proactive.running` or an underlying proactive answer drain not yet settled (coordinator cancellation can complete while retrieval continues), the transcript-embedding cache computing, `domain.mutating > 0` (a counter around each `_serialize` closure, which is how a meeting index, a pending-source drain or a Google refresh counts only while its helper operation runs and not while it waits in `waitForSourceWork`), or `_queryAcquisition` set (also a leased-operation guard). A scheduled but unfired `_enhance` timer is not busy: `Application.close` cancels it as today, whether it is the 30 s edit timer or the 3 s retry timer. Targeted edits start enhancement immediately. Durable work waiting on a paused source queue is not busy. A helper `_start` in flight is not busy either: `_close` first clears `helper.onReady` synchronously, preventing new resume work during recording cleanup, then terminates it as today (`Helper._close` awaits the probe and launch, and the ping loop returns on `stopping`), which the existing tests that run without a helper executable depend on.

**Exit**, desktop branch, armed only by a last desktop departure: at least `desktopDetachGrace` (1 s) since that departure, still `_desktopClients.isEmpty && !access.hasHost`, no non-`status` agent lease waiting for helper readiness or operation dispatched or in cancellation cleanup, and, at the time of departure, `lastAgentActivity` unset or (`serviceIdleMinutes > 0` and `now - lastAgentActivity >= serviceIdleMinutes`); with the period disabled, any past agent work keeps the service alive after a desktop departure. Of the rest of the busy list only `domain.mutating > 0` applies (Decision 1: an executing serialized mutation of any origin, such as the indexing drain a large import scheduled, which runs detached from the request that scheduled it); `close()` cancels everything else as today, and the close itself still finishes an active recording's transcription and meeting indexing before cleanup completes, which the desktop-branch `TestRecording` test and the explicit-stop subprocess case pin, so busy item 2 need not hold this branch. A departure that does not arm the shortcut leaves the idle branch in charge. **Exit**, idle branch: `_desktopClients.isEmpty && !access.hasHost`, not busy, `serviceIdleMinutes > 0`, and `now - lastAgentActivity >= serviceIdleMinutes`, with service start standing in for a never-attached service. `status` leases neither advance `lastAgentActivity` nor postpone either exit. When only the grace or the period guard fails, `_exitIfIdle` reschedules itself for the remaining time instead of waiting for the 30 s tick, so an exit is late only by timer slack.

**The close.** `_exitIfIdle()` evaluates `_shouldExit()` and calls `close()` with no acknowledgement client and without a yield between them; it sends no reply and does not consult `shutdownVerified`, exactly like today's desktop timer callback. `Application.close` rejects new business calls before its first await and cancels the Google, live-index, inactivity and enhancement timers there, and the proactive timer one microtask later when no query acquisition is in flight (otherwise after that acquisition is closed, as today), so background work cannot start between the check and the close. The exit is worker-initiated, so the frontend relay's draining and refusal behavior from fix-plan 3.4 applies, and `_close` destroys idle agent sockets, whose `ServiceConnection` reconnects on its next call. `_stopIfIdle` shares `_busy` and additionally refuses with `busy`, before closing, while the helper's adoption probe or child launch is unresolved (`helper.starting`, meaning completion flags around `_startupProbe` or `_launching`, whose future fields are not cleared, never the ping loop or `onReady`), and when the helper is adopted (`adopted || snapshot != null` with no owned process) and the identity probe cannot run or `fs_process_matches` returns neither "gone" nor "matches"; a positively gone identity is verifiable, and a helper that ignores SIGTERM still fails after teardown as today. The automatic exit does not wait for the probe, but `_close` already keeps the endpoint record unless helper shutdown is verified. `stop_if_idle` stops a desktop-pinned idle service as today, which keeps the installer contract.

## What each client owns

| Capability | Owner | When the owner leaves |
|---|---|---|
| Approval host (`security.*` decisions, import-root grants) | Desktop | Pending approvals fail; new approval-requiring calls fail at once with `denied`, reason `needsDesktop`. Unchanged except the added reason. |
| Recording and its on-screen indicator | Desktop | Recording stops immediately (ADR 0006). Transcription of what was captured finishes in the service. Unchanged. |
| Process lifetime | Desktop, by presence | Desktop leaves with no agent work within the period: exit after 1 s. Otherwise: exit one idle period after the last agent request, with nothing busy. |
| Storage reads, notes, local search, local answers | Service | Available to any same-user client while running. |
| Imports, deletes, clears, model and account changes, web search | Service, under desktop approval | Only with a live desktop's per-operation approval and, for files, an import-root grant. Without a desktop they fail fast. |
| Google refresh timers and reminders | Service | Run while the process does. |
| Explicit stop (`--stop`, `--stop-if-idle`, SIGTERM) | Operator and installers | Authoritative for everyone, with ADR 0003's closing protocol. |

| Who is connected | Process exits when |
|---|---|

## Changes

1. **`ApplicationService`:** replace `_desktopShutdown` with `_lifetime`, one timer that owns the periodic reevaluation, the event-driven checks and the reschedules for the remaining grace or period, and that `_close` cancels; retain `desktopShutdownScheduled` as the armed desktop shortcut before close (the 1 s grace and `desktopDetachGrace` stay); add `lastAgentActivity`, `lastDesktopDeparture`, `_busy` (extracted from `_stopIfIdle`, shared with it, extended by the busy list), `_shouldExit()` and `_exitIfIdle()`. `ApplicationService.start` accepts `clock` and `createTimer` and passes them to `Domain` so tests drive the period without sleeping. `Domain` gains `mutating` and completion flags for its initialization and resume futures; `Domain.waitForSourceWork` and `Domain.index` accept an optional `current` cancellation callback that `Application.call` forwards through imports, refreshes, Google imports and refresh, shared meeting indexes and recording-stop waiters, so a cancelled operation parked on a paused queue settles at once; `Application` gains `backgroundBusy`; `ReferenceNoteTranscriptCache` gains `computing`, counting every unsettled embedding drain including work whose entry was invalidated, cleared or evicted, decremented only when each drain settles; `Helper` exposes `adopted` and `starting` (adoption probe or child launch pending); `ApplicationService` tracks each dispatched operation until its work and its stream cleanup settle. Delete the comment in `_accept` about agent connections keeping models alive and say the new rule in one line.
2. **`_stopIfIdle`:** use `_busy`; refuse with `busy` before closing while `helper.starting`, and when `helper` is adopted and its identity cannot be verified, keeping the existing "could not be verified" wording so the Dart test changes only the error type.
3. **`RpcErrorReason.needsDesktop`:** additive enum value on ADR 0003's enum and `reason` on the existing "Open the desktop app" denial. MCP copies `reason` into `structuredContent.error`.
4. **Status:** additive `lifetime` object: `{"pinned_by_desktop": bool, "busy": bool, "last_agent_activity": ms | null, "idle_minutes": double, "exit_after": ms | null}`. `exit_after` is the earliest time the close can begin: the end of the grace on the desktop branch, the end of the idle period on the idle branch, and `null` while a desktop pins the service, while the idle branch is busy, or when `serviceIdleMinutes` is 0 and no shortcut is armed. Busy work can postpone it, and cleanup follows it. `--status` prints it.
5. **Preference** `serviceIdleMinutes`, stored as a minute string like `inactivity` and parsed with `double.tryParse`, with a Settings row next to the recording inactivity setting offering Never, 15, 30 (default), 60 and 120 minutes; stored values outside the list are included as an extra item. Fractional values such as `0.05` round-trip as a JSON number; tests seed Store directly or use an attached approval host before its reader starts.
6. **Docs:** the table above replaces the lifetime sentences of the "Shared operation and lifecycle" paragraph in `application-service.md`, keeping the lock and capture sentences, and "neither client disconnect unloads the generator" becomes "models are released only when the process exits"; "The next client starts a service again" becomes "attaches while the service is still running, otherwise starts one"; "Google reminders and refresh timers run in the service, independent of an open desktop window" becomes the sentence in Consequences; a `denied` error gains `reason: needsDesktop` when no approval host is attached; the status field list and the `get_status` tool row gain `lifetime`; the `--stop-if-idle` paragraph gains "and background model work"; the overview's "inactivity shutdown" gains "idle exit"; `README.md`'s "closing the MCP client does not unload a model" and `docs/platforms/macos-support.md`'s "Closing a window or an MCP client does not shut down the service" become "the desktop keeps the service running; after it leaves, desktop-only use keeps the one-second shutdown grace, and recent agent use follows the busy-aware idle rule, so models are released one idle period after the last agent request whether or not the agent is still connected"; `docs/validation/issue-142-functional-followups.md`'s "independent headless service ownership is preserved" is annotated as superseded by this ADR and its "background-lifetime product decision" points here; `README.md`'s feature bullet "a background service that keeps running and keeps models loaded after the window closes" becomes "a background service that stays warm while the window is open and, after recent agent use, until one idle period has passed"; `docs/platforms/macos-support.md`'s "Recording, final transcription, or another active operation defers the upgrade" gains "or executing background model work"; `services/inference/README.md`'s "Stop the existing application service before launching an upgraded bundle" gains "or wait for its idle exit". The coverage matrix (`docs/architecture/service-lifecycle-tests.md` on the integration branch) files the idle exit under "Closing" for the MCP and desktop rows.

Wire compatibility: all additions are optional fields. An older MCP sees a service that exits after it has been idle for the period and reconnects on its next call as it already does. An older desktop is unaffected. An older service against a new client behaves as today.

## Tests

Production code on both sides, timers and clock injected, no sleeps for ordering. Short periods use fractional `serviceIdleMinutes`: in-process and child-process Dart tests seed Store; Python tests set it through the attached ApprovalDesktop before its review reader starts. `preferences.set` is approval-gated and is not an MCP tool.

1. Agent-only service: one `notes.list`, then the injected clock passes `serviceIdleMinutes`. The service closes through the closing path, the record and socket are removed, and the lock is released. The next `ServiceConnection` call launches exactly one replacement and succeeds after at most one resend (`notSent`). A service launched by a host that only called `get_status` exits after one period.
2. Agent-only, one-shot: the agent disconnects right after a request; the service stays for the period; a second agent connecting before it attaches to the same pid; after it, relaunches.
3. Desktop and agent: the desktop closes while an agent `meetings.generate` is held by a fixture generator (or an `answer.stream` fixture is running). Recording (if any) stops at once, the stream completes with its real result, the service keeps its pid, and exits one period after the stream completed.
4. Desktop branch: an agent completes a request, the clock passes the period, a desktop attaches, works, and closes; the service exits after the 1 s grace. A desktop is attached while an agent completes a request, then the desktop closes within the period; the service waits for the idle period. A desktop opens and closes while an agent is mid-request; the request completes and the service waits for the period. An agent request that runs longer than the period is still in flight when the desktop closes; it completes, and the service exits one period after it settles. A desktop closes with an agent's last activity 29 minutes old and no agent connected; the service exits one minute later through the idle branch, and ageing past the period does not shorten that. A desktop closes during a model load with no agent activity; the close cancels the load as today. A desktop closes while its own import's indexing drain is executing; the close begins when the drain settles. `status` polling faster than once per second does not postpone an exit. `serviceIdleMinutes = 0` disables the idle branch and leaves the desktop branch.
5. Busy conditions each hold the idle exit and release it when they clear: active recording, finishing recording, a running import, an executing meeting index, model configuration guarded by its lease, an automatic note enhancement fired 30 s after a `meetings.notes` edit, a proactive answer, a `Domain.resume` in progress, a cancelled `notes.save` whose committed work is still gated (then `stop_if_idle` refuses until the work is released). `stop_if_idle` before the helper's adoption probe resolves refuses with `busy`. A paused source queue with pending work does not hold it, and neither does a helper `_start` in flight (the no-helper fixture exits within the grace as today).
6. A request arriving during an idle close gets `closing`. Dispatched non-status work holds both automatic exits, so `outcomeUnknown` remains covered by explicit stop and SIGTERM, including a dispatched status that races another exit event; status may always be resent.

## Not in this change

- **Model unload with a resident process** and `backgroundSync`: alternative (e), its own ADR when wanted.
- **A session-scoped daemon**: alternative (f).
- **Changing ADR 0006.** Recording still stops the moment the host leaves.
- **Root package hooks stopping services.** A root hook cannot discover profiles; the refusal stays as today while the service holds the lock.
- **An automated idle stop of a mismatched-revision owner from the desktop's startup path.** Drafted as a typed `ServiceRevisionMismatch` result, a `stopIdleIncompatibleOwner` flag passed only by `RemoteDomain.connect`, and an `unless_pinned` argument to `stop_if_idle`; dropped because the mismatched owner now exits by itself within one idle period, and because the load-bearing guard (send the stop only to an owner whose reply carries `lifetime`, since an older owner would ignore `unless_pinned`) is easy to get wrong. Revisit if users report the manual message.
- **Deferring the MCP adapter's service connect to its first tool call.**
- **`tools/install_macos.py` ergonomics** (`--profile` implying `--stop-services`): unrelated to lifetime; fix-plan backlog.
